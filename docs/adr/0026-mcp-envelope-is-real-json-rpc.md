# The `mcp` envelope becomes real MCP — JSON-RPC 2.0 over `/agent/mcp` — because a badge that says MCP and isn't one is exactly what the conformance badges exist to catch

`/agent/mcp` has answered `{"tool": "...", "input": {...}}` → `{"protocol": "mcp", "result": {...}}` since B1. That is a REST-ish lookalike, not the Model Context Protocol: no JSON-RPC 2.0 envelope, no `initialize` handshake, no `tools/call` method name, and `tools_list()`'s schemas are a loose `{"sku": "string"}` shorthand rather than JSON Schema. `wellknown.py` advertises this endpoint under `"mcp"` in the agent-commerce card and the protocol registry's conformance badge (`registry.py`, `badge()`) reports it as the MCP protocol. Both are currently a claim the wire format doesn't back up — the thing ADR-0016's badge work exists to prevent, just pointed at our own transport instead of a translated one.

This surfaced now because Phase 2 wants the buyer-chat demo to be a generic MCP client — the same kind of client that could point at Anthropic's own reference servers or anyone else's — rather than a bespoke caller hardcoded to this repo's tool names. A generic client speaks real MCP or it speaks nothing; there is no shorthand version of the wire format worth building a client against.

**Decision.** `/agent/mcp` now accepts JSON-RPC 2.0 requests and implements the three methods this sidecar has a use for: `initialize` (capability negotiation, no session state kept beyond echoing `protocolVersion`), `tools/list` (JSON Schema `inputSchema` per tool, plus `annotations.readOnlyHint`/`destructiveHint` derived from the tool's `Scope` so a generic client can build a sane default permission tier without knowing any tool by name), and `tools/call` (dispatches to the same `_run_tool`/`_dispatch` core every envelope already shares — UCP/ACP/AP2 translators are untouched, this changes only the MCP envelope's shape). No resources, no prompts, no sampling: this sidecar has never exposed any of those and inventing support for the sake of spec completeness would be exactly the over-building this project's own ADRs argue against elsewhere.

No back-compat shim for the old shape. A demo two commits old that still posts `{"tool": ...}` gets a JSON-RPC parse-error response, which is correct: it was never speaking MCP, and a translation layer that accepted both would let the fake shape keep working invisibly, which is the bug this ADR exists to close.

**Consequences.** Every direct caller of `/agent/mcp` in the test suite (`test_tools.py`, `test_refund_queue.py`, `test_purchase_live.py`, `test_agent_surface.py`, `test_card_golden.py`, `test_protocols.py`) is updated in the same change to send `{"jsonrpc": "2.0", "id", "method": "tools/call", "params": {"name", "arguments"}}` and read `result.structuredContent`. `docs/CODES.md` and `SPEC.md`'s MCP references get the corrected shape. The badge's MCP conformance claim is now true rather than asserted.
