# A Listing Index is a phonebook, ranking is the buyer agent's job

ADR-0005 already ruled out a crawler, ranking, or hosted search in v1, and PLAN-distribution.md's standing rule already says the sidecar "never crawls, ranks, submits ... reach is achieved by being ingestible, not by being an intermediary." Both predate an actual Index design, so neither says what an Index is allowed to be once one exists. Left unstated, the natural next step — OpenStore runs the Index, so OpenStore should also rank results, feature merchants, or gate who appears — turns the phonebook into a mall with a different owner. This ADR makes the boundary a design constraint on the Index itself, not just a promise about the sidecar.

A Listing is a signed, self-published record a Merchant's own sidecar emits: category, region, protocols, pubkey, sidecar URL, `verified_as_of`. An Index is a queryable store of Listings, filtered by category and region only — no relevance score, no featured placement, no manual curation step between publication and appearing in results. Ranking is left entirely to the Directory Client (the agent or human doing the querying), the same way a phonebook lists every subscriber alphabetically and leaves "best plumber" to the caller. The Reference Index OpenStore runs is not privileged: it is one Mirror among any number of independently-run ones reading the same open Listing feed, and a second Index needs zero coordination with OpenStore to exist. If the Reference Index ever became the only place a Listing could be found, it would be load-bearing, and a load-bearing Index is a mall regardless of what it charges.

Concretely, this rules in: filtered lookup (category + region → matching Listings, those being exactly the axes the Listing format carries), a published and versioned Listing format and query API so a Mirror can be built without asking, domain-ownership proof at registration (reusing ADR-0012's well-known-challenge pattern), a signed withdrawal that removes a Listing on receipt rather than making a closed shop wait out a sweep, and a re-verification sweep as the backstop for a sidecar that goes dark without withdrawing. Withdrawal is the Merchant's own lever and the only removal lever anyone has: an Index that could not honour it would be holding merchants in against their will, which is a mall's relationship, not a phonebook's. It rules out: any sort order derived from anything but the query itself (no popularity, no recency-as-relevance, no paid placement), any manual accept/reject step on an individual Listing beyond the automated domain-ownership and re-verification checks, and any Index-side feature that only the Reference Index gets (a second-class Mirror is a chokepoint by another name).

Consequences: a merchant that publishes a Listing gets the same visibility as every other conformant Listing in its category and region, on every Index, forever, with no OpenStore-side lever to promote or suppress it beyond the abuse controls (domain-ownership proof, minimum listing age, per-Index rate limits) that apply uniformly. A future monetized offering — hosted Index, compliance-as-a-service, enterprise support — must be sold on top of this guarantee, not by weakening it; charging for placement inside the Index is the one business model this ADR forecloses.
